Inside the KnotTransformer

Every matrix, every multiply, every number — traced through one complete forward pass.

We use a toy example: 4 points, dimension 4, 1 attention head. The real model uses 6+ points, dimension 64, 4 heads — but every operation is identical, just bigger matrices.

Why three separate matrices?

Without projections (raw dot product hi·hj): can only find "points that look like me." Two points with different features get a low score even if they're highly relevant to each other.

With projections: the model learns what to ask for (Q), what to advertise (K), and what to send (V) independently. The sharp bend D₂ can ask "who else is bending?" (Q) while advertising "I'm the sharpest point" (K) and sending "here's my curvature data" (V) — three different things.

3Attention scores: Q · KT

Every point's question gets compared against every point's sign. This is a single matrix multiply that produces an N×N similarity matrix.

scores[i][j] = Qi · Kj = Σd Qi,d × Kj,d

Example: scores[2][1] = Q₂ · K₁
= (0.03)(0.49) + (0.36)(0.84) + (1.07)(0.93) + (1.40)(0.16)
= 0.015 + 0.302 + 0.995 + 0.224 = 1.536
"D₂'s question matches D₁'s advertisement with score 1.536"

4Softmax → attention weights

Each row of scores independently gets turned into probabilities summing to 1. This is what determines "how much attention does each point pay to each other point."

weight[i][j] = exp(score[i][j]) / Σk exp(score[i][k])

Row 2: exp([0.17, 0.77, 0.86, 0.24]) = [1.185, 2.160, 2.363, 1.271]
sum = 6.979
weights = [1.185/6.979, 2.160/6.979, 2.363/6.979, 1.271/6.979]
       = [0.170, 0.309, 0.339, 0.182]  ← sums to 1.00

5Weighted sum of values

output[i] = Σj weight[i][j] × V[j]

6Residual connection + LayerNorm

The original input is added back, then the vector is normalized.

h₂_new = LayerNorm(h₂ + attention_output₂)

h₂ + out₂ = [0.30+0.554, 0.10+0.524, 0.90+0.630, 1.50+0.532]
         = [0.854, 0.624, 1.530, 2.032]

mean = 1.260,  std = 0.555

LayerNorm = [(0.854−1.260)/0.555, (0.624−1.260)/0.555, (1.530−1.260)/0.555, (2.032−1.260)/0.555]
         = [−0.73, −1.15, 0.49, 1.39]
Why add the original back? If attention learned nothing useful, the residual passes h₂ through unchanged. The model can never "forget" its own identity — it only adds context on top.
Why normalize? After adding, the numbers might grow large. LayerNorm rescales each vector to mean=0, std=1 across its dimensions, keeping values in a stable range for the next layer.

7Feed-forward network (per token)

Each token independently passes through a 2-layer neural network. Attention mixed information across tokens; the FFN processes each token's mixed information.

FFN(x) = GELU( x · W₁ + b₁ ) · W₂ + b₂

Expand:  4-d → W₁ (4×16 in real model: 64→256) → 16-d
Activate: GELU (smooth ReLU: keeps positives, squashes negatives)
Compress: 16-d → W₂ (16×4 in real model: 256→64) → 4-d

Then: h₂_final = LayerNorm(h₂_after_attn + FFN(h₂_after_attn))
Why expand then compress? The expansion to 4× width gives the network a bigger "thinking space" for nonlinear computation. GELU is the nonlinearity — without it, two linear layers collapse into one. Think of it as: drafting on a whiteboard (256-d) then summarizing onto a notecard (64-d).

That's one encoder layer. It consists of:

Input H (N×64)
  ↓ Q=HWQ, K=HWK, V=HWV  — three projections
  ↓ scores = Q·KT/√dk  — every point vs every point
  ↓ weights = softmax(scores)  — normalize to probabilities
  ↓ output = weights · V  — grab weighted content
  ↓ + residual + LayerNorm
  ↓ FFN (expand → GELU → compress)
  ↓ + residual + LayerNorm
Output H' (N×64) — same shape, new content

8Multiple attention heads

The real model uses 4 heads, each operating on 16 of the 64 dimensions. Each head can learn a different attention pattern.

Split: Q (N×64) → Q₁(N×16), Q₂(N×16), Q₃(N×16), Q₄(N×16)
      K (N×64) → K₁(N×16), K₂(N×16), K₃(N×16), K₄(N×16)
      V (N×64) → V₁(N×16), V₂(N×16), V₃(N×16), V₄(N×16)

Each head independently: headh = softmax(Qh·KhT/√16) · Vh → N×16

Concatenate: [head₁ | head₂ | head₃ | head₄] → N×64
Final: concat · WO → N×64
Each head learns its own N×N attention pattern using different dimensions
Why 4 separate patterns? Each head "sees" different features (dims 1-16, 17-32, etc.):
• Head 1 might learn: "attend to spatially nearby points"
• Head 2 might learn: "attend to points with similar curvature"
• Head 3 might learn: "attend to the endpoints for global context"
• Head 4 might learn: "attend to points on the opposite side of the curve"

The 4 patterns get concatenated, enriching each token from 4 perspectives simultaneously.

9Stacking 3 encoder layers

Each layer has its own WQ, WK, WV, WO, W₁, W₂. Different layers learn different patterns.

What each layer learns (intuitively)

Layer 1: Direct relationships. "D₂ notices D₁ and D₃ are its neighbors."

Layer 2: Indirect relationships. "D₂ already absorbed D₁'s info. Now D₂ attends to D₁ again, but D₁ already knows about D₀. So D₂ learns about D₀ through D₁."

Layer 3: Global context. "Every point now has full-sequence awareness. D₂ knows the total arc length, the overall shape, where the bends are."

After 3 layers: the encoder output is N vectors of 64 dimensions each. Same shape as input, but each vector encodes global geometric context. This is the encoder memory.

10The decoder: queries extract knots

The decoder has a different set of vectors — learned queries — that read from the encoder memory. Each query becomes one knot.

Two types of attention per decoder layer

Self-attention among queries
Q, K, V all come from the query vectors. Queries look at each other:
"Where are you placing your knot? I'll place mine somewhere different."
This prevents two queries from producing the same knot value.
Cross-attention to encoder memory
Q comes from queries, K and V come from encoder output:
Q = queries · WQ
K = encoder_memory · WK
V = encoder_memory · WV

Each query asks the encoded points: "What geometry do I need?"
Click a query (amber) to see which encoded points (green) it cross-attends to
Cross-attention shapes:
Q_cross = queries · WQ     → (Kmax+1) × 64  ← from decoder
K_cross = memory · WK     → N × 64             ← from encoder
V_cross = memory · WV     → N × 64             ← from encoder

scores = Q_cross · K_crossT / √16  → (Kmax+1) × N
weights = softmax(scores)         → (Kmax+1) × N
output = weights · V_cross        → (Kmax+1) × 64

Same Q·KT·V formula — just Q from one source, K and V from another.

11Knot head: vectors → ordered numbers

The guarantee: softplus(r) > 0 for any r → cumsum is strictly increasing → divide by total maps to (0,1). The output is always valid and always ordered by construction. No sorting, no constraint enforcement — the math makes it impossible to produce invalid knots.
