The Linear(6→64) projection lifts each token into the 64-dimensional space where attention operates. The position embedding adds a learned vector per position so the model knows ordering (position 0 vs position 3).

Step 2 — Encoder: points talk to each other

3 layers of self-attention. Every point "looks at" every other point and updates its representation based on what it learns. Click any point below to see its attention pattern.

Click any point in the top row to see what it attends to. Line thickness = attention weight.

Q = H·WQ, K = H·WK, V = H·WV
Attn(Q,K,V) = softmax(QKT / √dk) · V  // dk = 64/4 = 16 per head
What Q·KT computes
Every pair of points gets a "similarity score." High score = "this other point is relevant to me." The softmax turns scores into weights summing to 1.
What the output is
Each point's new vector = weighted average of all points' value vectors. Point D₁ might weight D₂ heavily (sharp turn nearby) and D₀ lightly (far away, gentle region).

After 3 encoder layers

Each point's 64-d vector no longer describes just that point — it describes that point in context of the whole sequence. The encoder probing results confirm this: linear probes recover chord fractions (R²=0.98), turning angles (R²=0.82), and local curvature (R²=0.76) from the encoder output. The model computes these geometric features through attention, not from hand-crafted formulas.

Step 3 — Decoder: queries extract the knots

The decoder has learned query vectors — blank slots that get filled by attending to the encoded points. Each query becomes one knot. Click a query to see its cross-attention.

Click any query (amber) to see which encoded points (green) it attends to.

Self-attention among queries
Queries coordinate with each other: "You're covering the first third of the curve, I'll handle the middle." This prevents knots from bunching up.
Cross-attention to encoder
Each query looks at the encoded points and asks: "What geometry do I need?" A query for the middle of the curve might attend heavily to the points where the sharpest turn happens.

Why DETR-style queries?

This architecture comes from DETR (object detection). There, queries become bounding boxes. Here, queries become knots. The key property: the number of queries is fixed (Kmax+1 = 7), but the number of used queries varies per sample. A 4-point input uses 3 queries (K=2 knots + 1 slack); a 6-point input uses 5. Padding masks handle this naturally.

Step 4 — Knot head: scores become ordered knots

Each decoded query produces a raw scalar. The output head turns these into valid, strictly ordered knots in (0,1).

Step A: raw scores r = MLP(decoded_query)
Step B: si = softplus(ri) + ε  // strictly positive increments
Step C: ci = Σj≤i sj  // cumulative sum → automatically increasing
Step D: ui = ci / cK+1  // normalize → all in (0, 1), last slot is the "slack"
Why this guarantees valid knots: softplus is always positive → every increment si > 0 → cumsum is strictly increasing → division by total maps to (0,1). No sorting needed. The ordering is by construction.

The gradient chain (backward pass)

∂E/∂θ = ∂E/∂u · ∂u/∂θ

∂u/∂θ = standard backprop through transformer  // PyTorch does this automatically

∂E/∂u requires differentiating through the linear solve:
  A(u)·P = D̃ → ∂P/∂uk = −A−1 · (∂A/∂uk) · P  // implicit differentiation
Why implicit differentiation?
The control points P are defined implicitly by AP = D̃. When a knot uk changes, A changes, and P must adjust to keep AP = D̃. The formula tells us exactly how much P moves per unit change in uk.
Self-supervised: no labels needed
The loss is just E — the curvature of the curve the model produced. Low curvature = good, high curvature = bad. The curve grades itself. Every step from knots to energy is differentiable, so the gradient flows all the way back to the attention weights.
